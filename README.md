# AI Travel Planner

A chat-driven trip planner: describe a trip in plain language, get a day-by-day
itinerary generated by a local LLM (via Ollama), stored in MySQL.

## Stack
- **Frontend**: Streamlit (chat UI)
- **Backend**: FastAPI + SQLAlchemy + Alembic
- **Database**: MySQL
- **LLM**: Ollama (local), swappable for a cloud provider later
- **CI/CD**: GitHub Actions — lint + test on every push/PR, build & push Docker
  images to GitHub Container Registry on merges to `main`

## Prerequisites
- Docker Desktop
- [Ollama](https://ollama.com) installed, with a model pulled:
  ```bash
  ollama pull mistral
  ```
  Make sure Ollama is running (`ollama serve`, or it may already run as a
  background service after install).

## Running locally (Docker Compose — recommended)

```bash
cp .env.example .env
docker compose up --build
```

- Frontend: http://localhost:8501
- Backend API docs: http://localhost:8000/docs
- MySQL: localhost:3307 (user `travel_user` / pass `travel_pass`) — mapped to
  3307 instead of the default 3306 in case you already have a local MySQL
  install using that port

The backend reaches Ollama on your host machine automatically via
`host.docker.internal`. If you're on Linux and this doesn't resolve, either
confirm Docker Engine ≥ 20.10 (it should support `extra_hosts:
host-gateway` out of the box) or run Ollama in its own container instead.

## Running without Docker (faster iteration while developing)

**Backend:**
```bash
cd backend
python -m venv .venv && source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# Point DATABASE_URL at a MySQL instance you're running some other way,
# or start just the MySQL service: docker compose up mysql
uvicorn app.main:app --reload
```

**Frontend** (separate terminal):
```bash
cd frontend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run streamlit_app.py
```

## Running tests
```bash
cd backend
pip install -r requirements.txt
pytest -v
```
Tests use an in-memory SQLite database and mock the Ollama HTTP call, so no
live MySQL or Ollama instance is needed to run them.

## Database migrations (once schema stabilizes)
Currently `main.py` calls `Base.metadata.create_all()` on startup for
convenience. Once you're iterating on the schema with real data you care
about, switch to Alembic-managed migrations:
```bash
cd backend
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

## How long trips are generated
Trips longer than a few days are generated in chunks (5 days per LLM call by
default) rather than one giant response — local models like mistral become
unreliable at producing long, unbroken JSON in a single call, and this keeps
each individual request small regardless of total trip length. A trip length
can be provided explicitly (the Streamlit UI has a "Trip length" field), or
left for the model to infer from the prompt itself. Requests are capped at
`MAX_TOTAL_DAYS` (60, configurable in `llm_service.py`) to avoid unbounded
generation time; longer requests are silently clamped and a note is returned
explaining the cap.

Expect multi-week trips to take a few minutes, since each chunk is a
separate sequential call to the model.
